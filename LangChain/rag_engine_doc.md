# 豫园 XR 导游 Agent - RAG 检索引擎技术说明

本文档详细描述了 `rag_engine.py` 的实现方案，旨在为学术论文提供核心技术架构说明。

## 1. 核心技术栈
本模块基于 **LangChain** 框架构建，集成了高效的文本处理与向量检索技术：
- **框架**: LangChain (2026 标准版)
- **向量数据库**: FAISS (Facebook AI Similarity Search)
- **嵌入模型 (Embedding)**: BAAI/bge-m3 (北京人工智能研究院发布的多功能模型)
- **文本切分策略**: RecursiveCharacterTextSplitter (递归字符切分器)

## 2. 文本处理流程 (Ingestion Pipeline)

### 2.1 语义切分 (Splitting)
为了保证检索到的知识片段具有完整的语义信息且长度适中，系统采用了 `RecursiveCharacterTextSplitter`。
- **切分逻辑**: 优先尝试在段落分隔符 (`\n\n`) 处切分，其次是换行符 (`\n`)，最后是标点符号 (`。`, `！`, `？`, `；`)。这种递归方式能最大限度保留句子的完整性。
- **参数配置**:
  - `chunk_size`: 300 字符 (平衡了上下文丰富度与检索精度)
  - `chunk_overlap`: 50 字符 (确保相邻分块间有上下文衔接，防止信息在切分点丢失)

### 2.2 向量化 (Embedding)
采用 **BGE-M3** 模型将文本转换为 1024 维的高维向量。
- **优势**: BGE-M3 在中文语义对齐方面表现卓越，支持长文本，且具备极强的跨语言检索能力，适合豫园景点的专业领域知识。
- **配置**: 使用 `normalize_embeddings=True` 进行余弦相似度优化。

## 3. 检索机制 (Retrieval)

### 3.1 向量存储与索引
使用 **FAISS** 构建本地索引。
- **索引类型**: `IndexFlatL2` (默认使用欧氏距离进行暴力搜索，在小型知识库中可保证 100% 的召回精度，响应延迟在毫秒级)。

### 3.2 相似度算法
系统支持两种检索模式：
1. **标准检索 (`similarity_search`)**: 直接返回与查询向量距离最近的 $k$ 个文档块。
2. **精细检索 (`similarity_search_with_score`)**: 返回文档及其对应的 L2 距离。系统通过公式 $Similarity = \frac{1}{1 + Score}$ 将距离转化为 0 到 1 之间的相似度分数，并根据预设阈值（如 0.6）过滤低相关度结果。

## 4. 听障优化适配
在 RAG 层级，系统不仅检索历史背景，还重点提取**视觉特征描述**（如“太湖石”、“巨龙形态”），为后续 Agent 生成具有强烈视觉冲击力的导游词提供素材。
